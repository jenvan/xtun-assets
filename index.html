xtun.

一个本地中转程序 + 一个公网入口，把内网和外网接起来。

内网机器主动连出去，因此不需要公网 IP、也不用在路由器上做端口映射。于是有两件事可用： 一是本机借服务器线路出网（本地起个 SOCKS5，浏览器配一下即可）； 二是把内网的 VNC / RDP / HTTP 服务按需暴露到外网，用浏览器就能访问。 反向隧道的会合点默认在 Cloudflare，也可以换成自己的 VPS。

代理上网 SOCKS5

给本机一个服务器侧出口

本地起一个 SOCKS5 端口，浏览器或程序配一次就用；流量从服务器线路出网。 适合统一出口、给内网里不能直连外网的机器上网，或需要按需切换线路的场景 — 隧道内是裸字节透传，TLS 端到端、不做 MITM。

远程桌面 VNC

浏览器里操作内网机器

无需公网 IP、无需端口映射，登录控制台点一下就能连。 用的是官方 noVNC 页面：缩放、压缩比、画质、剪贴板、全屏都在； 凭据按服务端要求自动切换（标准 VNC 与 macOS ARD 的账号/密码框不同）。

远程桌面 RDP

连公司 / 家里的 Windows

同样是浏览器里操作，但走 Windows 原生远程桌面： 侧替浏览器做完 X.224 协商与 TLS 终结，前端用 IronRDP。 多屏、画质、剪贴板更贴近原生；与 VNC 可同时开，各占一条设备条目。

内网服务开放 HTTP

给内网服务一个外网网址

NAS 管理页、路由器后台、开发中的站点……挂到 <设备>.<网关域> 就能从外网访问，不用端口映射； 支持流式响应与 WebSocket 透传（看板、实时日志、应用自带的 WS 都能用）。

自建中继（可选）

不想依赖 Cloudflare 时

反向隧道的会合点默认在 Cloudflare。也可以换成自己的 VPS：启动时把 -relay-url 指过去即可，其余配置与客户端都不用改（复用同一个协议）。 家里和公司都在同一座城市时，走自己的机器往往更快更稳； 而且中继域与网关域可同时访问同一个服务，哪边顺手用哪边。
